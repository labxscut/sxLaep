## Input Format (FASTA)

`sxlaep` reads protein sequences from a **FASTA** file.

### Minimal FASTA example

```fasta
>seq1 some description
MKVLWALIFLLKSAF
>seq2
GAVLKVLTTGLPALISWIKRKRQQ
```

### Formatting rules

- A FASTA record begins with a header line starting with `>`.
- The **sequence id** is the first token of the header line (before the first whitespace).
- The **description** is the full header line after `>`.
- Sequence lines may wrap; they are concatenated into a single sequence string.

### Newlines / encoding (Windows, WSL, Linux)

Transferring text files among **Windows / WSL / Linux / macOS** may change newline characters and/or encoding.
If you see unexpected parsing errors:

- Re-save the FASTA as **UTF-8**
- Prefer **LF** newlines when working inside WSL

### Recommended quick sanity check (parse-only)

Use the Python API to quickly confirm that your FASTA can be parsed:

```bash
python - <<'PY'
from sxlaep.fasta import read_fasta_records

recs = read_fasta_records("proteins.fasta")
print("records:", len(recs))
print("first_id:", recs[0].identifier)
print("first_len:", len(recs[0].sequence))
PY
```

Notes:
- Non-standard amino acids are sanitized automatically (only the 20 standard amino acids are used).
- Very short sequences (< 10 aa) may yield less reliable predictions.

## Computation (sxlaep)

sxLaep provides two command-line styles:

1) **Shorthand**: `sxlaep --input ...` uses the **bundled** model shipped in the installed package.
2) **Subcommand**: `sxlaep predict --model ...` uses a **custom** model file.

### Global usage (`sxlaep --help`)

```text
usage: sxlaep [-h] [-i FASTA] [-o CSV] [--lag LAG] [--weight WEIGHT]
              [--segments SEGMENTS] [--add-length] [--no-add-length]
              [--properties [{hydro,polar,charge} ...]]
              {predict} ...

sxLaep enzyme/non-enzyme classifier

positional arguments:
  {predict}
    predict             predict enzyme probabilities for FASTA sequences

options:
  -h, --help            show this help message and exit
  -i FASTA, --input FASTA
                        Shorthand: predict with the bundled model on this
                        FASTA (no predict subcommand).
  -o CSV, --output CSV  With --input only: output CSV path (default:
                        sxlaep_predictions.csv in the current directory).
  --lag LAG             pseudo-AAC lag (fixed to 10 for bundled model; use
                        `sxlaep predict` to customize)
  --weight WEIGHT       pseudo-AAC weight (fixed to 0.05 for bundled model;
                        use `sxlaep predict` to customize)
  --segments SEGMENTS   number of window-AAC segments (fixed to 3 for bundled
                        model; use `sxlaep predict` to customize)
  --add-length          append sequence length (fixed for bundled model; use
                        `sxlaep predict` to customize)
  --no-add-length       do not append sequence length (fixed for bundled
                        model; use `sxlaep predict` to customize)
  --properties [{hydro,polar,charge} ...]
                        physicochemical properties (fixed to hydro polar
                        charge for bundled model; use `sxlaep predict` to
                        customize)
```

## Quick prediction (bundled model) — `sxlaep --input`

This is the simplest and fastest way to run inference with sxLaep.

### Example command

```bash
sxlaep --input proteins.fasta --output predictions.csv
```

### What happens internally

- Loads the bundled model `enzyme_xgb_model.ubj` from the installed `sxlaep` package.
- Extracts alignment-free physicochemical features (fixed configuration for the bundled model).
- Writes a CSV file containing predicted labels and enzyme probabilities.

### Output location

- If `--output` is omitted, the default is `sxlaep_predictions.csv` in the current directory.

### Common mistakes

- **Bundled model not found**: shorthand mode expects a wheel/pip install layout. Install with:
  - `pipx install sxlaep` (recommended), or
  - `pip install sxlaep`
- **Mixing styles**: do not combine `--input/--output` with the `predict` subcommand in the same command.

## Prediction with a custom model — `sxlaep predict`

Use this mode if you have your own trained model file.

### Supported model file formats

- Native XGBoost formats: `.ubj`, `.json` (recommended)
- Legacy joblib/pickle formats: `.pkl`, `.joblib` (supported)

### Predict usage (`sxlaep predict --help`)

```text
usage: sxlaep predict [-h] --model MODEL --fasta FASTA [--output OUTPUT]
                      [--lag LAG] [--weight WEIGHT] [--segments SEGMENTS]
                      [--add-length] [--no-add-length]
                      [--properties [{hydro,polar,charge} ...]]
                      [--n-jobs N_JOBS]

options:
  -h, --help            show this help message and exit
  --model MODEL         trained joblib model path
  --fasta FASTA         input FASTA file
  --output OUTPUT       output CSV path
  --lag LAG             pseudo-AAC lag (must match training)
  --weight WEIGHT       pseudo-AAC weight (must match training)
  --segments SEGMENTS   number of window-AAC segments (must match training)
  --add-length          append raw sequence length to feature vector (must
                        match training)
  --no-add-length       do not append sequence length to feature vector
  --properties [{hydro,polar,charge} ...]
                        physicochemical properties for pseudo-AAC (must match
                        training; default: hydro polar charge)
  --n-jobs N_JOBS       number of parallel workers
```

### Example command (predict)

```bash
sxlaep predict \
    --model enzyme_xgb_model.ubj \
    --fasta query.fasta \
    --output results/query_predictions.csv \
    --lag 10 \
    --weight 0.05 \
    --segments 3 \
    --add-length \
    --properties hydro polar charge \
    --n-jobs 1
```

### Parameter notes (predict)

Feature extraction flags must match training:

- `--lag` (int): maximum correlation lag for pseudo-AAC.
- `--weight` (float): weight for sequence-order correlation terms.
- `--segments` (int): number of N-to-C windows for windowed AAC.
- `--add-length` / `--no-add-length`: append sequence length or not.
- `--properties` (list): one or more of `hydro`, `polar`, `charge`.

Parallelism:

- `--n-jobs` sets the number of worker processes used for feature extraction.

### Detailed option reference (predict)

The following section explains each `sxlaep predict` option in a “manual” style.

#### `--model MODEL`

- **Type**: path
- **Required**: yes
- **Meaning**: the trained model file to load.
- **Supported**:
  - XGBoost native: `.ubj`, `.json` (recommended)
  - Joblib/pickle: `.pkl`, `.joblib`
- **Tip**: prefer native `.ubj`/`.json` for portability and faster loading.

Example:

```bash
sxlaep predict --model enzyme_xgb_model.ubj --fasta query.fasta --output out.csv
```

#### `--fasta FASTA`

- **Type**: path
- **Required**: yes
- **Meaning**: input protein FASTA file.

Example:

```bash
sxlaep predict --model enzyme_xgb_model.ubj --fasta proteins.fasta --output out.csv
```

#### `--output OUTPUT`

- **Type**: path
- **Required**: no
- **Default**: `results/predictions.csv`
- **Meaning**: where to write the output CSV.
- **Note**: the parent directory will be created automatically.

#### `--lag LAG`

- **Type**: integer
- **Default**: `10`
- **Meaning**: maximum correlation lag used by pseudo-AAC.
- **Constraint**: must match training.
- **When to change**: only when you trained the model with a different lag value.

#### `--weight WEIGHT`

- **Type**: float
- **Default**: `0.05`
- **Meaning**: weight applied to sequence-order correlation terms in pseudo-AAC.
- **Constraint**: must match training.

#### `--segments SEGMENTS`

- **Type**: integer
- **Default**: `3`
- **Meaning**: number of N-to-C windows used by windowed AAC.
- **Constraint**: must match training.

#### `--add-length` / `--no-add-length`

- **Type**: flag
- **Default**: enabled (`--add-length`)
- **Meaning**: whether to append raw sequence length to the feature vector.
- **Constraint**: must match training.

#### `--properties [hydro polar charge ...]`

- **Type**: list of tokens
- **Default**: `hydro polar charge`
- **Meaning**: which physicochemical property tables are used by pseudo-AAC.
- **Constraint**: must match training.

Examples:

```bash
# default (explicit)
sxlaep predict --model m.ubj --fasta q.fasta --output out.csv --properties hydro polar charge

# if and only if your model was trained with fewer properties:
sxlaep predict --model m.ubj --fasta q.fasta --output out.csv --properties hydro polar
```

#### `--n-jobs N`

- **Type**: integer
- **Default**: `1`
- **Meaning**: number of parallel workers used for feature extraction.
- **Guideline**:
  - start with `2–4` and scale up
  - set to `1` if you want maximum reproducibility and minimal resource contention

### Shorthand mode notes (`sxlaep --input`)

When using the bundled model shorthand (`--input`), feature parameters are **fixed** (for consistency with the packaged model).  
If you pass feature flags such as `--lag` / `--weight` / `--segments` / `--add-length` / `--properties` together with `--input`, sxLaep will **ignore** them and print a warning.

Recommended patterns:

```bash
# Bundled model (fast screening)
sxlaep --input proteins.fasta --output predictions.csv

# Custom model (fully configurable)
sxlaep predict --model my_model.ubj --fasta proteins.fasta --output predictions.csv --n-jobs 8
```

### Recommended workflows

1) **Screening / gatekeeper** (large metagenomes):
   - run `sxlaep --input ...` to quickly filter out non-enzymes
   - keep high `enzyme_probability` sequences for downstream annotation

2) **Production inference** (fixed model):
   - pin your model file in version control or a released artifact
   - run `sxlaep predict --model ...` with a known parameter set

3) **Batch pipelines**:
   - split huge FASTA inputs
   - run multiple `sxlaep predict` jobs (each with a reasonable `--n-jobs`)
   - merge CSV outputs afterward

## Output

Both `sxlaep --input` and `sxlaep predict` write a **CSV**.

### Output columns

| Column | Meaning |
|---|---|
| `sequence_id` | FASTA record id (first token of the header). |
| `description` | Full FASTA header (everything after `>`). |
| `pred_label` | Predicted class (`0` = non-enzyme, `1` = enzyme). |
| `enzyme_probability` | Estimated probability of enzyme class (if the model supports probabilities). |

### CSV example

```csv
sequence_id,description,pred_label,enzyme_probability
seq1,seq1 some description,1,0.9231
seq2,seq2,0,0.1374
```

### Interpreting results

- `pred_label` is the model’s default decision (classification).
- `enzyme_probability` can be used for ranking and thresholding:
  - Sort descending to prioritize likely enzymes.
  - Choose a cutoff based on your tolerance for false positives/negatives.

## Speed Up

### Parallel feature extraction (`--n-jobs`)

For large FASTA inputs, feature extraction can dominate runtime. Increase parallel workers:

```bash
sxlaep predict \
  --model enzyme_xgb_model.ubj \
  --fasta big.fasta \
  --output big.csv \
  --n-jobs 8
```

Guidelines:
- Start with `--n-jobs 2` or `4` and increase gradually.
- Avoid overcommitting CPUs on shared machines.

### Chunking (very large datasets)

For very large datasets (e.g., 100k+ sequences), consider splitting a FASTA into multiple chunks and running multiple `sxlaep` processes, then concatenating CSV outputs.
